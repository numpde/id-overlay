Clean-Room State Machine Rewrite Protocol
=========================================

Objective
---------
Rewrite the extension around one explicit semantic state machine without
porting the current broken design.

The rewrite is not a line-by-line refactor. It is a contract-first cut-over:

- define user-observable behavior
- define canonical state, events, transition results, and history records
- implement the pure machine against that contract
- reconnect DOM, storage, transform math, and page adapters afterward
- delete the old duplicated ownership paths instead of preserving them


Core Risk
---------
The main risk is not losing code. The main risk is preserving the old design
under cleaner names.

The current implementation has several repeated single-source-of-truth breaks:

- durable session state also owns undo/redo snapshot semantics
- panel effects still perform durable mutations
- presentation derives user-facing history from store-level descriptors
- mode, status, and history are resolved in multiple layers
- DOM affordance guards can disagree with transition validity
- interaction adapters can become semantic authority

The rewrite succeeds only if these ownership splits disappear.


Clean-Room Rule
---------------
New machine code must not import the old transition stack.

Allowed to reuse directly:

- pure transform math
- image normalization and image policy helpers
- low-level coordinate conversion helpers, once their boundary is clear
- storage adapter mechanics, only as an opaque persistence boundary
- DOM/page adapter knowledge, only after the machine contract exists

Not allowed to port directly:

- snapshot undo/redo implementation
- panel live-effect durable mutations
- status-controller feedback composition
- UI history descriptor tables
- stale intent repair paths
- mode side effects hidden in low-level session helpers
- interaction controller methods as semantic APIs

If a current function mixes allowed and forbidden responsibilities, split the
allowed pure helper out only after its desired contract is restated in new tests.


Authoritative State
-------------------
The new machine owns one canonical UI state:

```js
{
  session: {
    mode,
    opacity,
    image,
    placement,
    registration: {
      pins,
      solvedTransform,
      dirty,
    },
  },

  runtime: {
    pointer: {
      screenPx,
    },
    activeGesture,
    inputOverride,
  },

  panel: {
    intent,
  },

  status: {
    messageOverride,
  },

  history: {
    past,
    future,
  },
}
```

Rules:

- primary facts live in the machine state
- derived status, button enabled state, labels, and tooltips are selectors
- persistence stores a durable projection, not runtime/panel/status/history by
  accident
- adapters may cache listener handles and timers, but not semantic state


Authoritative Events
--------------------
Events are user-semantic, not DOM-shaped and not store-action-shaped.

Initial event families:

- image lifecycle: paste requested, image loaded, image cleared
- mode selection: Trace selected, Align selected
- registration: pin added, pin removed, pins cleared, overlay fitted from pins
- placement: overlay moved, overlay rotated, overlay scaled
- panel intent: confirmation requested, confirmation cancelled, timeout elapsed
- history: undo requested, redo requested
- runtime input: gesture started, gesture updated, gesture ended, input override
  changed

DOM events and keyboard shortcuts are adapter inputs. They translate into these
events; they do not define the machine vocabulary.


Transition Result
-----------------
Every transition returns the same shape:

```js
{
  state,
  effects,
  feedback,
  historyRecord,
}
```

Rules:

- `state` is the complete next canonical machine state
- `effects` are external commands only, such as reading paste data or starting a
  timeout
- `feedback` is the semantic user-facing outcome, not a composed status string
- `historyRecord` is present only for undoable semantic edits

Undo/redo replay stored semantic events. They do not restore raw snapshots.


History Record
--------------
Undoable changes store semantic inverse/replay events:

```js
{
  kind,
  label,
  undoEvent,
  redoEvent,
}
```

Rules:

- the event determines mode when mode is meaningful to the user
- mode is not restored merely because it existed in a snapshot
- pure mode switches are not history and do not clear redo
- new semantic edits clear redo
- opacity is excluded from undo/redo unless the product decision changes


Required User-First History Behavior
------------------------------------
The target behavior is:

- loading an image is undoable as "Clear image" and redoable as "Reload image"
- clearing an image is undoable as "Restore image" and redoable as "Clear image"
- adding/removing pins undo/redo in Align because pins are visible there
- clearing pins undo/redo in Align because pins are invisible in Trace
- fitting from pins is undoable because Trace entry visibly changes the overlay
- moving, rotating, and scaling the overlay undo/redo without forcing the user's
  current mode
- pure mode switches do not enter history and do not destroy redo


Cut-Over Shape
--------------
The rewrite should be a clean cut-over, not an incremental transplant.

Phase 1. Contract tests

- replace the current controller-driven target tests with direct machine tests
- assert state, feedback, history labels, undo events, redo events, and effects
- include adapter-boundary tests only for translation into machine events

Phase 2. Pure machine

- add the new machine state constructor
- add selectors for derived UI/status/policy views
- add the reducer/transition function
- add semantic history replay inside the reducer

Phase 3. Adapters

- make panel, overlay, keyboard, storage, and page integration dispatch machine
  events
- make them render selectors and execute returned external effects
- keep timers, paste reads, DOM listeners, and page operations outside the
  machine

Phase 4. Deletion

- delete snapshot history from the durable session store
- delete panel live effects that mutate durable session state
- delete status fallback composition outside selectors
- delete interaction controller methods that are now semantic machine events
- delete duplicated descriptor/label tables
- delete stale-intent repair paths made impossible by canonical state


Acceptance Gates
----------------
The cut-over is not complete until:

- the target undo/redo posture tests are green against the new machine API
- unit, integration, contract, and build tests are green
- no new machine file imports old UI transition/history/effect modules
- no adapter owns semantic validity or history policy
- persistence writes only the explicit durable projection
- all user-visible labels/tooltips/status messages are derived from machine
  state, transition feedback, or pending history records
- old fossils are deleted rather than left as unused compatibility paths


First Implementation Move
-------------------------
Start by creating the new machine test battery and machine module in isolation.

Do not wire the extension UI first. Wiring first would force the new design to
imitate the old API. The first executable contract should be:

- initial no-image Trace/native state
- load image
- clear image
- select Align and Trace
- add/remove/clear pins
- fit overlay from pins
- move/rotate/scale overlay
- undo/redo for each meaningful user action
- selector output for panel controls, status, and overlay pass-through

Only after that contract is green should the content-script adapters be
rewired.
